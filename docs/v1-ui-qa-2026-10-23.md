## Findings blocking end-to-end readiness

### Resolved — ITC ledger balance was rejected by the Expense Warrior client

The Overview and Wallet pages request `/api/v1/expense-warrior/wallet/ledger-balance` and receive HTTP 502 `ITC_FINANCE_RESPONSE_INVALID`. The app therefore cannot show the authoritative ITC ledger available balance, although the separate provider-reported balance loads.

The source contract pointed to the zero-hold representation: ITC's `getBalance` query can return an empty hold sum as the integer string `0`; the service returned that as `active_holds`, while Expense Warrior validates money strings in exact two-decimal form (`0.00`). ITC now normalizes the display value to `0.00` while keeping cents arithmetic unchanged, and its regression test asserts the full response contract.

### P1 — All configurable expense-category mappings are unset

The Admin Team page loaded 36 configurable expense-category mapping selectors and all 36 are `Not mapped`. The stock/purchasing categories are intentionally excluded from OPEX mappings. Until the approved expense categories are mapped to valid ITC OPEX accounts, manager/admin approval and posting paths are not ready for use.

### P1 — No eligible staff/manager candidates or payout destinations are available

The initial candidate lookup returned no selectable staff or managers; a read-only search for `it` also returned zero candidates. The page reports no payout destinations and no manager assignments. This prevents testing staff request routing and configuring payout destinations. The result establishes what this Admin UI can currently select; it does not prove that no employee accounts exist in ITC.

### Resolved — A/R is now gated while the current ITC release defers A/R

The Payment links screen now labels “Delivered invoice balance (coming soon)” and disables that target unless `ITC_COMMERCE_RECEIVABLES_ENABLED=true`. The API defaults the flag off and returns `COMMERCE_RECEIVABLES_DEFERRED` before any ITC receivable call or link persistence. The current ITC release still defers A/R, so revenue and customer-credit remain the available paths.

### P2 — Loopback sign-in origin is rejected

Opening the frontend as `http://127.0.0.1:5175` caused ITC to return HTTP 403 `CORS origin denied` before checking credentials. The current LAN origin `http://192.168.10.58:5175` passed CORS and sign-in. Use the LAN URL for this phone/browser preview. Add the loopback origin to the isolated local development allowlist if direct localhost testing is needed; do not loosen production CORS.
